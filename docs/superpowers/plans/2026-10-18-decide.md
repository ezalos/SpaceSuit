# `decide` skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a global `decide` skill that agrees the frame, every ideal-outcome axis and the
catastrophes with Louis, then does the option search and Pareto pruning in the
background. It keeps a private decision record.

**Architecture:** a lean `SKILL.md` holds the flow (calibrate, then frame + axes + MUSTs
in one playback, then options, consequences and pruning, then gated questions, then
output). The heavy content lives in `references/` and is loaded per step or lens. Testing
follows TDD for skills (superpowers:writing-skills):

- **RED:** an invented eval set runs without the skill to record a baseline.
- **GREEN:** the skill is written, and the same set runs with it.
- **REFACTOR:** a dev-only replay of the two private sessions, done under the no-copy
  rules, finds the remaining gaps.

**Tech Stack:** markdown skill files, the Agent tool for evals and option sub-agents,
`claude -p` for the private replay, and `claude-log` for observability. The deploy uses
the `src_dotfiles` skills fan-out.

**Spec:** `docs/superpowers/specs/2026-10-17-decide-design.md` (read it in full first).

## Global Constraints

- Skill dir: `skills/decide/`. Frontmatter `name: decide`, `user-invocable: true`.
- SpaceSuit is **public**. Nothing from Louis's private cases goes in any file,
  including this plan: no names, places, figures, organisations or case-specific details.
  Examples are invented and generic. The pre-commit content scrub is a backstop, not the
  check.
- The private term list and the two dev-replay session IDs live **only** in
  `~/.config/decide/private-dev` (mode 0600, outside any repo). The executor writes that
  file from the design conversation. Format:
  - a line `session <uuid>` for each replay source;
  - then one private term per line (the names and organisations the case material
    contains).
- Records go in `~/Decisions/YYYY-MM-DD-<slug>.md`, never in any repo. The skill creates
  the dir with mode 0700 on first use.
- No numeric weights and no weighted sums. Dominance plus Even Swaps only.
- When another party has a say, the output is a menu, never "the answer".
- Full mode: frame, stakeholders, axes and MUSTs in **one** phone-sized playback ending
  "what's wrong or missing?".
- MUST checkpoints: before outbound text, before a commit, before an irreversible step,
  and after a compaction.
- Sub-agents never put record details into web queries.
- Observability contract (`docs/plans/2026-04-21-skill-storage-observability-design.md`
  §4):
  - an `## Observability` section;
  - at least one `claude-log decide …` call;
  - the name matches the frontmatter.

  Log messages carry **no decision content**: a step name and a generic event only
  (`feedback; step=axes; added an axis`), never the axis itself.
- Every file opens with a 2-line `ABOUTME:` comment. For markdown that means an HTML
  comment placed after the frontmatter.
- Commit straight to `master` and push after each task. Stage only the files you touched.

## Review Focus

1. **A one-line ask with nothing else** ("help me decide X"). The skill must still do the
   framing playback, not jump to options. Pinned by eval scenario S1 (Task 1).
2. **"Just quick" on an irreversible, high-stakes decision.** Quick mode runs, but the MUSTs
   are named and irreversibility is flagged once. Pinned by eval scenario S4.
3. **A constraint arriving after the background search started.** It goes in the constraint
   log, and the running agents get it with no restart. Pinned by the S3 injected late
   constraint.
4. **The other party's interests completely unknown.** They are labelled as assumptions
   with a confidence level, and the most important ones become questions Louis can ask.
   No guessed fact is stated as true. Pinned by S1 and S3.
5. **A session cwd inside a git repo.** The record is still written to `~/Decisions/`, and
   `claude-log` lines carry no content. Pinned by the Task 4 check.

### Task 1: Eval set and baseline (RED)

**Files:**
- Create: `skills/decide/evals/scenarios.md`
- Create: `skills/decide/evals/rubric.md`
- Create: `skills/decide/evals/README.md` (how to run it, and the baseline results table)

**Interfaces:**
- Produces: scenario IDs `S1`–`S4`, the rubric criteria IDs `R1`–`R8` used in Tasks 3–4,
  and a baseline score row per scenario.

The scenarios are invented. Each one has:

- the opening message Louis would type;
- `hidden facts`, which the simulated Louis reveals only when asked;
- a reference axis list, with each axis marked `obvious` or `often-missed`;
- reference option families (at least 5 distinct);
- reference MUSTs;
- the expected lens and output shape.

The scenarios:

- `S1`, negotiation: a salary and package talk for a new role.
  - Often-missed axes: leverage timing, equity versus cash, title, remote and
    location flexibility, start date, the relationship with the future manager.
  - The counterparty's interests are unknown.
- `S2`, design: choose a job-queue architecture for a small service.
  - Often-missed axes: operability at 3am, cost to run, reversibility (migration cost),
    time to ship.
- `S3`, negotiation + design: splitting roles between two co-founders and a newcomer.
  - Expected output: a menu, never a single split.
  - **Late constraint:** after the playback, the simulated Louis adds "one of them must
    own research".
- `S4`, quick mode: "just quickly, should I sign this 3-year lease or a 1-year one".
  - The irreversibility must be flagged.

The rubric, one line each, each pass/fail with a count where noted:

- `R1`: the frame and the principal are stated before any option.
- `R2`: axis recall, as the number of often-missed reference axes named in the playback
  out of the total.
- `R3`: the stakeholder interests are present, and every guessed one is labelled.
- `R4`: the MUSTs are explicit, and a pre-mortem item appears.
- `R5`: the option families, as the count of distinct reference families covered (out
  of at least 5) plus any novel valid ones.
- `R6`: no dominated option in the final set, and each survivor's losing axis is named.
- `R7`: the output shape matches the lens (menu when another party has a say).
- `R8`: there are 2 or fewer questions in total, and each could change the Pareto set.

- [ ] **Step 1: Write the three files**

  In the README, state the run procedure:
  - one Agent per scenario, given the opening message and a "simulated Louis" brief
    holding the hidden facts;
  - a separate judge agent scores the transcript against the rubric;
  - the judge never sees the reference lists until it grades.

- [ ] **Step 2: Run the baseline**

  Run S1–S4 with a general-purpose agent told "help Louis decide; do not use any skill".

- [ ] **Step 3: Record the baseline**

  Put the R1–R8 scores per scenario in the README table.

  Expected: low R2 and R5 scores, and R7 failing on S3. If the baseline already passes
  most criteria, the scenarios are too easy. Harden them (make more axes
  `often-missed`) before going on.

- [ ] **Step 4: Commit**

  ```
  git add skills/decide/evals/
  git commit -m "decide: eval scenarios, rubric and baseline"
  ```

  Push.

### Task 2: Write the skill (GREEN)

**Files:**
- Create: `skills/decide/SKILL.md`
- Create: `skills/decide/references/axes.md`: the often-forgotten checklist from spec
  step 2, the engineering quality attributes, and the "why does that matter?" ladder.
- Create: `skills/decide/references/option-strategies.md`: one ready brief per generation
  strategy (extreme per axis, strategy-table combine, wait or buy time, reframe, analogy,
  other-side package), plus the merge, dedupe and diversity-recheck rule.
- Create: `skills/decide/references/pruning.md`: consequences as ranges, MUST filter,
  dominance, Even Swaps with a worked invented example, sensitivity points, and the
  value-of-information question gate.
- Create: `skills/decide/references/lenses.md`: choice, negotiation (interests, BATNA,
  joint frontier, MESOs) and design (set-based, ATAM points, ADR). It includes the
  output templates and the combination rule.
- Create: `skills/decide/references/record-template.md`: front matter (`date`, `slug`,
  `lens`, `mode`, `status: open|decided`) and the sections listed in the spec ("The
  decision record").

**Interfaces:**
- Consumes: the spec, and the rubric IDs from Task 1. The skill must satisfy R1–R8
  without naming them.
- Produces: `SKILL.md` steps 0–7 plus quick mode. Each step names the reference file it
  loads.

Rules for `SKILL.md`:

- Under ~200 lines.
- The description starts with "Use when". It lists the triggers from the spec:
  - `/decide`;
  - "help me decide";
  - "what are my options";
  - "trade-offs";
  - "should I X or Y".
- **Step 0** decides mode and lens, then runs the freshness check: search the context
  before asking anything.
- **Steps 1–3** are one playback, using the format fixed in the Global Constraints.
- **Step 4** dispatches the option sub-agents in parallel. Each gets the record path and
  one strategy brief from `option-strategies.md`, plus the no-private-details-in-web-
  queries rule.
- **Late constraints** are appended to the record's constraint log, and the running agents
  are messaged with them.
- **MUST checkpoints** cover the moments listed in the Global Constraints and survive the
  end of the skill.
- **The record path** is stated in the chat.
- **Observability section:** the universal baseline, plus these skill-specific triggers:
  - INFO `axis added by Louis after playback`;
  - WARNING `MUST breached or nearly breached`;
  - INFO `diversity recheck ran a second round`;
  - INFO `quick mode chosen on irreversible decision`.

  Messages carry no decision content.

### Task 3: Dev-only private replay (REFACTOR)

**Files:** none are created. This task's output exists only in the conversation and as
skill-text edits to Task 2's files.

**Interfaces:**
- Consumes: `skills/decide/SKILL.md` and the rubric R1–R8.
- Produces: a list of gaps, each named in the abstract, then the skill edits.

The sources are the two transcripts named by the `session` lines in
`~/.config/decide/private-dev`. Each is found with
`ls ~/.claude/projects/*/<uuid>.jsonl`.

- [ ] **Step 1: Run the replay**

  For each transcript, run one headless replay from the shell and capture stdout only:
  ```
  claude -p --disallowedTools WebSearch,WebFetch,Write,Edit,NotebookEdit "<prompt>"
  ```

  The prompt tells it to:
  - extract the user and assistant text with `jq` (no tool results);
  - pick the 2–3 biggest decision moments;
  - for each one, apply `skills/decide/SKILL.md` as of that moment, using only what was
    known then;
  - score R2, R3, R5 and R7 against what Louis actually raised later;
  - report only scores and abstract gap names (for example "missed: leverage timing").
    No quotes, names, figures or places.

  Nothing goes to a file: no `>`, no `tee`, no scratchpad.

- [ ] **Step 2: Screen the output before relaying**

  Before relaying or using the output, read it. If it holds any concrete private detail,
  discard it and re-run with the prompt tightened.

- [ ] **Step 3: Fix the gaps**

  Turn each gap into a generic edit to the skill or its references. The wording must be
  invented, with no trace of the case. Re-run Task 2's privacy grep.

- [ ] **Step 4: Re-run the evals**

  Re-run S1–S4 and confirm there is no regression. Update the eval README row.

- [ ] **Step 5: Commit**

  ```
  git add skills/decide/
  git commit -m "decide: gaps from dev replay"
  ```

  The message names no case. Push.
